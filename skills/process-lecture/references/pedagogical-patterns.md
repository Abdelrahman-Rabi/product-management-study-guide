# Pedagogical Patterns

Use these structures to organize transcript-grounded teaching. Reuse the structure, never facts or wording from another lecture. Select the smallest pattern that serves the learning outcome; do not force every pattern into one guide.

## Pattern Selection

| Transcript structure | Preferred pattern | Learning purpose |
|---|---|---|
| Two ideas differ in consequential ways | Comparison | Prevent category confusion |
| One condition produces downstream effects | Causal chain | Explain why an outcome occurs |
| A PM must choose among options | Decision model | Make judgment criteria visible |
| Results inform the next action | Feedback loop | Show learning and iteration |
| Work moves through ordered states | Process | Clarify sequence and handoffs |
| An idea is easy to oversimplify | Misconception repair | Replace an attractive wrong model |
| A concept must be applied | Worked example | Demonstrate transferable reasoning |
| Several terms form a hierarchy | Definition ladder | Show how concepts nest or specialize |

## Comparison

Use when differences change interpretation or action.

```text
Shared context -> Dimension of difference -> Consequence -> When each applies
```

Compare on equivalent dimensions. Do not create a table whose rows merely restate definitions.

## Causal Chain

Use when the lecture explains why something happens.

```text
Condition -> Mechanism -> Immediate effect -> Product consequence
```

Do not imply causality when the transcript states only correlation or sequence.

## Decision Model

Use when the learner must evaluate or choose.

```text
Decision -> Relevant evidence -> Trade-off -> Choice -> Expected consequence
```

Keep criteria grounded in the transcript. Do not add an external prioritization framework.

## Feedback Loop

Use when outcomes or evidence change later decisions.

```text
Act -> Observe -> Interpret -> Adjust -> Act again
```

Make the feedback signal and changed decision explicit.

## Process

Use when order matters.

```text
Trigger -> Step -> Decision point -> Next step -> Result
```

Distinguish a required sequence from a teaching simplification or common pattern.

## Misconception Repair

Use only for a plausible misunderstanding supported by the transcript.

```text
Misconception -> Why it seems plausible -> Correct model -> Changed PM behavior
```

Do not include a shallow denial without repairing the learner's mental model.

## Worked Example

Use for required Level 2 and Level 3 practical examples.

```text
Situation -> Decision -> Reasoning -> Consequence -> Transferable lesson
```

Name the concept demonstrated by the example. Prefer one complete example over several fragments.

## Definition Ladder

Use when terms are related by scope or dependency.

```text
Foundation term -> Specialized term -> Operational meaning -> Example
```

Define only terms necessary for the lecture. Keep glossary wording consistent.

## Visual Pattern Choice

Match visual form to the relationship:

- Comparison: aligned columns or matched paths
- Causal chain: directed flow
- Decision model: decision tree or evidence-to-choice flow
- Feedback loop: cycle
- Process: numbered sequence with decision points
- Definition ladder: hierarchy or nested levels

Recommend one visual only when it makes the relationship easier to understand or recall than prose or a compact table.
